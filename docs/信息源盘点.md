# 信息源盘点：有多少通道可用，每类能取到什么

> 生成：2026-11-02　口径：本机网络环境实测（curl + 无头浏览器），非推测。
> 这份表的用途：下次要查某个平台的某条规则时，先看这里判断"该走哪条道"，而不是从零乱试。

## 三、一个容易混淆的区分：**市场数据** ≠ **平台规则**

Zalora 是典型：

- **能拿到**：5 万个商品 URL（`/p/品牌-型号-颜色-ID`）、类目树（robots 明确 Allow `/c/*`）
  → 足以反推**标题结构、品牌分布、价格带、上架节奏**
- **拿不到**：图片规格、标题字符上限、必填属性
  → 这些在卖家中心里，SPA + 登录墙

**这两件事必须分开说**：一个平台"能取数据"不代表"能取规则"；反过来，规则拿到了也不代表能算市场。

目前的项目只吃"规则"（`data/specs/platforms/`），没吃"市场数据"。如果要做竞品分析/选品，Zalora 这类"只有市场数据"的平台反而有用 —— 这是另一条产品线，不是这一轮要做的。

## 四、逐通道的实操要点（下次直接用）

### T2 文档站：三种形态，三种打法
1. **纯 HTML**（Shopee 卖家教育、noon 帮助中心文章页）→ 直接 curl，秒下
2. **SPA 需渲染**（Lazada 开放平台、Amazon developer-docs）→ 无头浏览器，`document.body.innerText`
3. **Markdown 直出**（Yandex）→ 页面末尾加 `.md`，最省事

### T3 `llms.txt`：先试它，再考虑抓 HTML
```
https://<站点>/llms.txt
```
- 有真索引 → 全站 Markdown 链接一次拿全
- 返回 HTML → 这个站没有，放弃这条
- **试过有真索引的**：Amazon、Yandex

### T4 sitemap：拿"有哪些页面"，不拿"页面写了什么"
- noon 的 sitemap → 492 篇帮助文章 → 全量抓 → 找到标题规则
- Zalora 的 sitemap → 5 万商品 → 但商品页里没有卖家规则
- **robots.txt 里搜 `Sitemap:`** 是最快找到它的方式

### T5 Wayback：curl 不通不等于拿不到
- 本机 curl 到 archive.org 返回 `000`，**浏览器能通**
- CDX 索引 API 在浏览器里可读：`web.archive.org/cdx/search/cdx?url=<目标>&output=json`
- 拿到 timestamp 后：`web.archive.org/web/<timestamp>/<url>`
- **用途**：登录墙页面的历史快照（Amazon 帮助页就是这么拿到的）

### T6 搜索引擎：绕登录墙最有效的一条
- 不带 `site:` 的泛搜价值低；**带 `allowed_domains` 限定到目标站**才有用
- 搜索引擎的摘要里常带完整正文，等于绕过登录墙
- noon 245 篇、Amazon 规则都是这么发现的

### T8 站内数据
- **SPA 的 API 在 JS bundle 里**：下 `/assets/index-*.js`，grep `/api/`（Zalora 找到 `/api/v2/`）
- **前台 JSON 接口**：先看页面有没有 `__NEXT_DATA__` / JSON-LD
- **robots 的 Allow 行**告诉你哪些路径是允许抓的（Zalora 允许 `/c/ /s/ /p/`）

### T9 人群：还没系统用
这是唯一还没开发的一类。可用入口：
- 中文：知无不言、亿邦、雨果网、各平台卖家微信群
- 英文：Reddit（r/ecommerce、r/FulfillmentByAmazon）、Quora
- 俄语：VK 卖家群、Дзен、Pikabu
- 视频：YouTube 实操录屏（**能直接看到后台界面长什么样**，这是截图级证据）

| 目标 | 最可能的路 | 代价 |

**最值得下一步做的一件事**：把所有平台的规则，用 YouTube 后台录屏做一次交叉验证。
因为录屏能直接看到"图片上传框写的最小尺寸是多少""标题输入框的计数器到多少变红"——这是**截图级 L2 证据**，比任何文档都硬。
