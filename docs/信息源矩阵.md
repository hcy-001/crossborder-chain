# 信息源矩阵：不同地区到底能取到什么（2026-10-29 实测）

> 只读探测，不绕过任何反爬与登录。证据：`out/verification/signal-sources.json`

## 一、一句话结论

**能自动取到数据的只有两类：汇率（全地区）+ 自有店铺 Seller API（仅俄罗斯）。**
其余地区的外部趋势信号**没有合规的自动源**，只能靠人工取样产出工单。这不是配置里写一串 `allowed` 就能解决的。

## 二、逐源实测

| 源 | 档位 | 实测 | 能取什么 | 说明 |
|---|---|---|---|---|
| fx-rates（汇率） | **A 自动** | ✅ 200 | USD/CNY、USD/各目标币 | 定价必需；已有实现与缓存 |
| Ozon Seller API | **B 需授权** | ✅ 200（带凭证） | 类目树、属性字典、属性取值、商品/价格/库存 | 6 个域实测可用；不带 header 时返回 401「headers are required」——是缺凭证，不是不可达 |
| VK API | B 需授权 | ⚠️ 需 token；本机直连不稳定 | 俄语社媒帖与互动量 | 无 token 返回 `error_code 8 version is required`；两次直连一次 200 一次 network_error → 不能算稳定源 |
| Yandex Wordstat | B 需登录 | ⚠️ 200 但需登录 | 俄语搜索词频 | 页面可达，**查数据要登录账号**，无公开 API → 200 不代表能用 |
| Ozon 前台搜索 | C 不做 | ❌ 307 跳转 | 竞品价格/款式 | 前台接口有反爬，不绕过 |
| Wildberries 公开 API | C 不做 | ❌ 403 | WB 商品与热榜 | WAF 拦截；开发者文档有浏览器校验 |
| TikTok / Instagram | C 不做 | ❌ 本机直连失败 | 东南亚/中东社媒趋势 | 无公开趋势 API；抓页面属绕过反爬 |
| 平台搜索页人工取样 | **B 人工** | ✋ 人工 | 价格、销量线索、评价数 | 无 API 地区的唯一合规路径：人工抄 20 条 → 工单 |

## 三、逐地区：信息怎么来

| 地区 | 平台 | 自动获取 | 可行路径 |
|---|---|---|---|
| 俄罗斯 RU | ozon / wildberries | 汇率 ✅；Ozon 自有店铺 API ✅ | 店铺数据走 API；趋势靠人工取样或第三方服务 |
| 阿联酋 AE | noon | 汇率 ✅ | 人工取样（noon 无公开 API） |
| 沙特 SA | noon | 汇率 ✅ | 人工取样 |
| 新加坡 SG | shopee / lazada / tiktok-shop | 汇率 ✅ | 人工取样 |
| 马来西亚 MY | 同上 | 汇率 ✅ | 人工取样 |
| 泰国 TH | 同上 | 汇率 ✅ | 人工取样 |
| 菲律宾 PH | 同上 | 汇率 ✅ | 人工取样 |
| 印尼 ID | 同上 | 汇率 ✅ | 人工取样 |
| 越南 VN | 同上 | 汇率 ✅ | 人工取样 |

**所以 8 个非俄地区的"前期信息获取"目前只能靠人。** 这不是我偷懒，是这些平台没有合规公开接口、且我不做绕过反爬的事。要做自动化，只有两条路：买商业数据服务，或拿到平台合作方权限。

## 四、这轮改了什么（针对"信息获取没迭代"的批评）

| 之前 | 现在 |
|---|---|
| `profile.json` 里只写 `allowed: [tiktok, instagram…]` 名单，没有一行实现 | 建 `data/signal-sources.json` 注册表：档位（A/B/C）+ 准入条件 + 实测状态 |
| 没人验证过这些源能不能用 | `npm run signals:probe` 实测 8 个源，出矩阵与证据 |
| 误判：把 Wordstat 标成"不可用"、把 Ozon API 的 401 当"不可达" | 按实测修正：Wordstat = 需登录（200 但取不到数据）；Ozon = 缺凭证（带上就 200） |
| `chain` 采集为空只说"没有工单" | 改为按地区给路径：哪条能自动、哪条要人工、哪条不做 |

## 五、没做到的（必须说）

1. **没有做真正的"多地区多品类采集"**。目前只验证了"源可达性"，没有跑真实采集产出工单——因为没有合规源。
2. **非俄地区 8 个法域的信号层是空的**，只有汇率。任何声称"能自动选品"的说法在这些地区都不成立。
3. **VK 稳定性存疑**：两次探测结果不一致（200 / network_error），不能当生产依赖。

已把"人工取样"这条路做成一条命令（`npm run signals:sample`）：抄一张 CSV（名称/链接/价格/币种/评价数/销量）→ 合规工单，带 `manual_sample` 来源三件套与置信分级，链路可直接消费。取样本身仍然是人做 —— 这是合规约束，不是实现偷懒。
