# Agent 施工契约

## 交付格式

每个实现 agent 只返回摘要，不返 transcript，摘要固定五项：

1. 结论：完成项与验证级别 L0/L1/L2。
2. 落位：新增和修改的精确路径。
3. 证据：命令、退出码、关键真实输出、产物大小。
4. 未决：没有则写“无”；不得把本轮应修问题转成待办。
5. 越界：是否改了授权目录外文件；正常应为“无”。

## 硬边界

- 严格按任务书列出的目录写入；共享文件由主 agent 唯一修改。
- 不改七条不变式、24 条已决策项和修订后的“零 key + 联网”口径。
- 不自行增加 npm scripts；四条对外命令保持唯一。
- 不把 secondary 数据写成 official，不编造费率、税率、时效或平台规则。
- 不用删除测试、注释检查、放宽判据来消除失败。
- 新门必须先做绿/红触发测试；只有命令真实退出码算证据。
- 每个任务结束返回可复跑命令，不接受“我看过了”。

## 接口变更

发现接口缺口时，实现 agent 在摘要中给出所需字段、消费方与最小修改建议；主 agent 修改 `schemas/` 或共享契约后再继续。不得在自己的模块里另建同义字段绕过。

## 提交纪律

主 agent 统一集成与提交。实现 agent 不执行 `git commit -a`，不修改其他工作流文件，不启停浏览器，不发起上架、外发或付费调用。
