# ADR 0001 · 定价口径：平台费按售价抽，用分母法反推

- 状态：已采纳（2026-10-29）
- 取代：初版"成本加成"实现

## 背景

初版定价把佣金、支付手续费、VAT 当成"到岸成本的百分比"加进去，再按目标毛利率放大：

```
成本项合计 = (采购 + 运费) × (1 + 佣金率 + 税率 + 手续费率)
建议售价   = 成本项合计 / (1 − 目标毛利率)
```

看起来合理，但有一个隐含前提是错的：**这三项都是按成交价抽的**，不是按采购成本抽的。佣金按成交额、手续费按流水、VAT 含在售价里。

## 决策

改成"从售价反推"（分母法），把所有百分比项放到分母：

```
保本价 P0 = 固定成本 / (1 − 佣金率 − 税率 − 支付费率)
目标价 P  = 固定成本 / (1 − 佣金率 − 税率 − 支付费率 − 目标毛利率)
```

同时支持两种目标口径，并显式标注：

- 毛利率 = (售价 − 成本) / 售价 → 用上面的分母法
- 加成  = (售价 − 成本) / 成本 → P = 保本价 × (1 + 加成率)

## 证据

同一组输入（采购 67 + 运费 33，佣金 18% / 税 6% / 手续费 2%，目标毛利 30%）：

| 实现 | 售价 | 佣金（应为 售价×18%） |
|---|---|---|
| 旧（成本加成） | 180.00 CNY | 18.00 |
| 新（分母法） | **227.27 CNY** | 40.91 |

差额 47.27 CNY ≈ 573 RUB/件。按旧价卖，每件亏约 573 卢布。

公式出处：公开毛利计算器与教材口径一致（`margin = markup / (1 + markup)`，`markup = margin / (1 − margin)`，售价反推 `P = 成本 / (1 − 毛利率)`）。

## 后果

- 回执里必须给**自洽明细**：固定成本 + 佣金 + 税 + 手续费 + 利润 = 售价（误差 ≤ 0.03），并有测试锁定毛利率精确落在设定值。
- 费率 + 毛利 ≥ 100% 时返回 `margin_unreachable`，**不给一个假价**。
- `total` 字段语义固定为"保本价"（保留字段名以防回执结构断裂），建议售价走 `target.price`。

## 为什么值得单独记一条

这是一个**看起来对、算出来亏**的错误：所有中间量都是正数，没有任何异常，只有把"谁按什么基数抽成"想清楚才会发现。留档是为了下次改定价的人不再踩同一个坑。
