## 三、取数协议（新增平台照这个走）

1. **T1 官方 API**：官方 Seller/Partner API 只读拉取（需凭证）→ 事实为 L2，status=final
2. **T2 官方文档**：官方帮助/开发者文档（公开）→ 事实为 L2 文本，需人工确认是否同样适用于该法域
3. **T3 后台/人工**：后台截图/卖家手抄 → 事实为 L1，status=candidate，必须在真机核对后升级

判定规则：只有 final 事实才能产出"可提交"的包；candidate 只能产出待核包；unverified 不参与生成

## 四、这份表能回答什么

- 某个法域现在能不能出**可提交**的包（不能的话卡在 API 凭证、文档缺失、还是后台字段）；
- 新增一个平台要补多少事实（看 `平台事实` 那列是不是 0）；
- 平台事实里有多少只是二手来源（`candidate` 列非 0 就说明还没到 L2）。

它**不能**回答：某条规则在具体叶子类目是否成立 —— 那必须用该类目的 type_id 实拉一次。
